# 0012 — Agent operating rules are generated, not authored

- **Status:** Accepted
- **Date:** 2026-08-10
- **Deciders:** Project owner

## Context

An agent that adopts this framework needs a small set of operating rules at the point it starts work:
that `audit` is an evidence survey and `validate` is the verdict, that a skipped rule is not a pass,
that standards and tests are never weakened to obtain green output, that results are never
manufactured, that work requiring independent human review is never self-attested.

Every one of those already exists as canonical text — in a standard requirement, a rule id, or a
decision record. Writing them into a project's `AGENTS.md` therefore runs directly into
[Standard 17](../../standards/17-agent-instruction-files.md) R2:

> A copied standard is a **fork**: it is edited independently, it drifts, and an agent following it
> eventually contradicts the canonical document while believing it is compliant.

R2 is not a style preference. It observes that agents read the instruction file *first* and trust it,
so the copy wins in practice — duplication does not merely risk drift, it makes the fork
authoritative. The tension is real and cannot be waved away by asserting the copy will be kept in
step, which is exactly what every fork asserts at the moment it is created.

## Decision

**The block is generated by the framework and rewritten in place, and it is an index rather than a
restatement.**

Three properties do the work, and each answers a specific way the copy could become a fork:

**One editable source.** `scripts/agent-instructions.mjs` holds the rules; `standards init` writes
them between `<!-- BEGIN standards:agent-operating-rules -->` and its `END` counterpart. An edit made
inside the markers is replaced on the next run and the block says so about itself, so a project-local
divergence cannot accumulate unnoticed. What R2 prohibits is a copy that is *edited independently*;
a generated region is not one.

**Every line names what governs it.** A rule with no citable source does not belong in the block,
because a free-floating prohibition is precisely the untraceable copy R2 rejects. The citations are
resolved mechanically — a test opens each cited standard and asserts the requirement heading exists,
and checks each cited rule id against the catalog. A pointer to a requirement that is not there is
worse than no pointer: it reads as canonical backing and leads nowhere.

**It states its own subordination.** The block says it is an index, that the canonical text governs
where the two disagree, and that following it is not a substitute for reading the standards. Without
that sentence it reads as the authority, which is the mechanism by which a bootstrap copy displaces
the thing it points at.

**The version is stamped from `VERSION`, through the same reader as the policy stamp.**
`frameworkVersion()` in `scripts/init.mjs` is the only place that decides what version governs a
bootstrap; a second read elsewhere would be a second implementation of one decision
(`architecture.no-duplicate-implementations`). An instruction block that does not say which revision
it indexes is unfalsifiable: a current index and one written two majors ago look equally
authoritative, and a reader has nothing to check.

**Generation goes through the same helper as the dry run.** `plan()` and `apply()` both call
`renderTemplate()` and nothing else. A transformation applied on one path and not the other produces
a dry run that promises what the real run does not do (Standard 33 R5) — and it would also break
idempotence, because `plan()` would compare a written file against the ungenerated template and
report a conflict against text `init` had itself produced.

## Consequences

**Existing adopters are not upgraded.** `init` still refuses to replace an `AGENTS.md` that exists
and differs, so a project bootstrapped under an earlier version keeps its old block and receives a
conflict report rather than a rewrite. That is the [Standard 33](../../standards/33-bootstrap-experience.md) R2
contract working as designed, and it means the stamped version is doing real work: it is what tells a
reader the block is behind. There is no regeneration command yet.

**The block cannot grow without bound.** Its length is pinned by R2's own test — an instruction file
must be shorter than the standard it routes to — applied to the generated output rather than to the
template. A line that needs a paragraph of explanation is a line whose explanation belongs in the
standard it cites.

**It remains instruction generation, not enforcement.** Nothing here checks that an agent followed
the rules. `validate` is the authority and CI is the gate; the block only ensures an agent is pointed
at them before it starts rather than after it has claimed completion. Treating a written instruction
as a control would be the same enumeration-over-mechanism mistake recorded in
[ADR 0007](0007-cli-scripts-are-single-run-programs-with-module-scoped-state.md).

**`scripts/agent-instructions.mjs` holds no module-level run state.** Its exports are frozen
constants and pure functions, and the framework version arrives as a parameter rather than a read, so
the governed set in ADR 0007 is unchanged by this addition. That was a design constraint rather than
an outcome, for the same reason it was one when the repository seam was opened in
[ADR 0011](0011-attestation-freshness-is-repository-content-not-checkout-bytes.md).

**This change stales `ai.destructive-approval`.** `scripts/init.mjs` is one of that attestation's
reviewed paths, and freshness is computed from committed repository content, so modifying init
correctly returns the rule to unestablished until a human re-reviews it. Recomputing the digest
instead would be the provenance substitution ADR 0011 forbids.

## Deferred

- **A regeneration command.** Bringing an already-bootstrapped project's block up to a new version is
  manual today.
- **Checking a consuming repository's instruction files.** `audit` still does not look for them, or
  compare their length against the standards they point at — the check Standard 17's Implementation
  section has recorded as missing since 1.0.0.
- **Detecting a stale block.** The version is stamped and therefore readable, but nothing compares it
  to the version the project's policy declares.
